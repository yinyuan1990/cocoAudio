  • echo 模式（默认）：服务器把收到的语音原样回传，用来单独验证一端（App 或设备）的音频通道是否正常。

给硬件同学：你们的 ESP32 直接连 ws://8.162.5.160:40000，按第 5.2 节的设备协议注册、接听、收发语音即可，不必等任何第三方。

1系统是做什么的

心声 是一套基于 WebSocket 的远程语音对讲（VoIP 对讲机）系统。手机 App 输入一个 6 位设备 ID 呼叫对应的硬件设备，接通后双向实时传语音（手机说话→设备喇叭，设备麦克风→手机听筒）。App 还能远程管理设备：查在线、扫描/配置 WiFi、调麦克风音量、切换联网方式、恢复出厂、配对。

三个角色：手机 App（主叫/管理端） — 云服务器（转发中枢） — 硬件设备 ESP32（被叫/终端）。App 与设备不直接通信，全部经服务器转发。

项目值
通信方式WebSocket 长连接
联调服务器ws://8.162.5.160:40000（我方已部署）
信令格式JSON 文本帧
语音格式二进制帧，IMA-ADPCM，8kHz / 单声道 / 16bit
设备标识6 位数字 ID
心跳每 15s 发 {"type":"ping"}，5s 内无回包则重连

4语音编解码规范（★ 端到端必须完全一致）

这是硬件端必须逐字节对齐的部分格式已固定并验证。设备收到的、发出的都必须是这个格式。

4.1 PCM 参数

参数值
采样率8000 Hz
声道 / 位深单声道 / 16bit 有符号，小端
每帧采样点 / 字节480 点 / 960 字节
每帧时长60 ms

4.2 ADPCM 打包格式（每个 WebSocket 二进制帧 = 1 个 251 字节包）

偏移长度内容说明
0–34魔数 "ADPC" = 0x41 0x44 0x50 0x43帧同步头
41版本 = 0x01
51采样数低字节 = 0xE0480 = 0x01E0，samples=data[5]|(data[6]<<8)
61采样数高字节 = 0x01
7–82首个 PCM 采样值（int16 小端）预测器初值 valpred
91步长索引初值（0–88）
101保留 = 0x00
11–250240ADPCM 数据（479 个 4bit 码，低 nibble 在前）
要点标准 IMA/DVI 4-bit ADPCM；步长索引在帧间连续传递，通话开始复位为 0；解析时以 251 字节为单位、用魔数 ADPC 对齐重同步。参考 C 常量表见工程 AdpcmCodec。

6硬件端需要实现的功能

  1. 联网：开机连 WiFi（保存的 SSID/密码），连不上进入配网模式（首次配网方式：AP 热点或蓝牙，由设备端设计）。
  2. WebSocket 客户端：连 ws://8.162.5.160:40000，断线自动重连 + 心跳。
  3. 注册：连上后发 connect_device + 6 位 ID。
  4. 来电/接听：收 incoming_call → 回 call_accept → 进入通话。
  5. 音频：ES8388 采集 8kHz PCM → IMA-ADPCM 编码 → 251 字节二进制帧发送；收二进制帧 → 解码 → 喇叭放音。
  6. 管理指令：WiFi 扫描/配置、麦克风音量、恢复出厂、切网、配对 GPIO。
  7. 挂断/掉线：收 call_ended 或断线时停止音频、回到空闲。
务必注意：回声/啸叫App 端没有做回声消除(AEC)。若设备用外放喇叭，喇叭声会被自己麦克风收回造成回声/啸叫。设备端需自行做 AEC，或用听筒/半双工方案。这是最容易翻车的点。

7ESP32-A1S 匹配性结论

结论：匹配 ✔（WiFi 语音对讲完全够用）

淘宝的 安信可 ESP32-A1S / ESP32-Audio-Kit（ESP32 + ES8388 音频编解码芯片）：

需求是否满足
WiFi 联网（WebSocket）✔ 802.11 b/g/n
麦克风采集✔ ES8388 双 ADC + 麦放
喇叭放音✔ ES8388 双 DAC + 功放
8kHz/16bit 单声道✔ I2S 可配置
IMA-ADPCM 编解码✔ 纯软件，双核 240MHz 绰绰有余
麦克风音量调节✔ ES8388 寄存器可调

需注意

  1. “切换 4G”：A1S 只有 WiFi、无蜂窝。要 4G 版需外挂 4G 模组（UART）。纯 A1S 只能做 WiFi 版。
  2. 买 ES8388 版本（AC101 版已停产）。
  3. 引脚随板子版本不同，以到手原理图 V2.3 为准（常见：I2C SDA=33/SCL=32，I2S BCK=27/WS=25/DOUT=26，功放使能 GPIO21）。
  4. 供电 5V/≥1A，否则 WiFi 发射时易掉电重启。
打样建议直接买 ESP32-Audio-Kit（ES8388 版）即可连我们的联调服务器跑通 WiFi 语音对讲全流程。

8快速联调步骤（硬件方）

  1. ESP32 连上 WiFi，建立到 ws://8.162.5.160:40000 的 WebSocket 连接。
  2. 发送 {"type":"connect_device","device_id":"123456"} 注册（ID 与 App 里输入的一致）。
  3. 用 App（心声）输入 123456 呼叫；设备收到 incoming_call 后回 call_accept。
  4. 进入通话：麦克风 PCM→ADPCM→发二进制；收二进制→解码→喇叭。先用听筒或小音量避免啸叫。
  5. 联调时联系我方把服务器切到 relay 模式（默认 echo 用于单端自测）。
先做最小验证硬件同学可以先不接 App：连服务器（echo 模式）后，自己发一帧 251 字节 ADPCM，能原样收回即说明"连接+收发二进制"通道正常，再逐步加入真实音频。
